# 原件定点回写（fixed-point rewrite）

接收方已经能把主机原件解码成业务字段。本功能把人工确认的少量更正**按字节定点
写回原件**：只改每个被确认字段占据的字节，其余位置一字节不动，输出一份新的
原件和机器可读的字节变更凭据。它**不重新编码整条记录**，因此原件里的填充区、
未选中的 REDEFINES 视图、非标准但合法的符号写法都会原样保留。

- 仅依赖 Python 标准库（≥ 3.9），沿用现有布局解析结果，不扩展 Copybook 语法。
- 原件按块流式读取，整份文件不会常驻内存；内存只容纳更正单、编译后的布局和
  当前一条受限记录。
- 任何失败都返回非零，并且不留下可被当成完成的交付目录。

## 命令

```bash
python3 -m copybook rewrite ORDER.json ORIGINAL.bin \
    --out-dir delivery/2026-11-15/ \
    --temp-dir /var/tmp/rewrite-tmp/ \
    --copybook-base copybooks/
# 可选：--chunk-size 1048576 --max-record-bytes 16777216
```

Python 接口：

```python
from copybook.rewrite import rewrite_original

evidence = rewrite_original(
    "order.json", source_path="ORIGINAL.bin",
    output_dir="delivery/2026-11-15/",
    temp_dir="/var/tmp/rewrite-tmp/",
    copybook_base="copybooks/")
```

退出码：`0` 成功；`2` 更正单/摘要/坐标/冲突/写出失败等任何拒绝（不产生正式
结果，原有 `decode` 等入口保持不变）。

## 更正单格式（UTF-8 JSON）

```json
{
  "source_sha256": "<原件完整 SHA-256，64 位小写十六进制>",
  "layouts": {
    "A": {"copybook": "ORDA.cpy", "name": "ORD-A", "version": "1",
          "codec": "cp037"},
    "B": {"copybook": "SUMB.cpy", "name": "SUM-B", "version": "1",
          "codec": "cp500"}
  },
  "records": [
    {
      "byte_start": 6,
      "byte_end": 50,
      "layout": "A",
      "record_sha256": "<该记录跨度的 SHA-256>",
      "edits": [
        {"path": ["ITEM-GROUP", 0, "ITEM-AMOUNT"],
         "expected_hex": "0012345c",
         "value": "405.04"}
      ]
    }
  ]
}
```

- `source_sha256`、每条记录的 `record_sha256` 都在发布前对**实际字节**重新计算
  核对，声明值不能代替计算值。
- `layouts` 是具名目录；同一原件可混合布局，codec 仅支持 `cp037` 与 `cp500`。
- `byte_start/byte_end` 是从文件起点计算的**非负整数半开区间**（bool 不算
  整数）；长度必须等于该布局的 `record_length`，不能越界，记录区间互不重叠或
  重复。列表可乱序。区间之间的头、换行、填充等字节属于原件，直接保留；不依赖
  换行寻找记录边界，COMP-3 中恰好为 `0A` 的字节也不会切开记录。
- 原件可以有未列出的记录；`records` 和 `edits` 都允许为空（空更正仍产出摘要
  一致、零变化的完整结果）。

### 单个 edit

- `path`：从记录根组的**孩子**起算的数组。命名层用布局里的大写字段名（小写会
  被转大写）；固定 `OCCURS > 1` 的数组层用从 0 开始的整数索引，每层 OCCURS 都
  必须显式给索引，不能凭末级同名字段猜位置。索引不能为负或 bool。
- 路径只能定位到**非 FILLER 的基本字段**；组、整数组、匿名填充项不可写。
  REDEFINES 的基字段和任一替代视图都可显式指定，不从判别字段或内容猜选视图。
- `expected_hex` 必须恰好覆盖该基本字段的原始字节，对**未修改的原件**逐条核对；
  同一记录前一项更正不会变成后一项的“原值”。
- 路径不存在或不能唯一定位、类型错误、旧值不符、未知布局、缺必要成员都会拒绝
  整次作业。JSON 重复成员、`NaN`/`Infinity`、浮点数一律拒绝。

### 新值编码（严格按现有 PIC 容量）

- `PIC X/A`：只接受字符串，按所选单字节编码转换后**右补该编码的空格**；不能
  截断、不能替换不可编码字符、不隐式 `str()`。空字符串补成全空格。
- `PIC 9/S9`（可含 `V`）：只接受十进制字符串，语法
  `-?[0-9]+(?:\.[0-9]+)?`；不接受加号、指数、空白、千分位或 float。小数位可少于
  scale 并右补零；超出 scale（哪怕多的是零）拒绝。精确缩放后的绝对值必须
  小于 `10**总数字位数`，不能截断。无符号 PIC 拒绝任何负值（含 `-0`）；有符号
  负零按非负零写。全程用整数/字符串运算，不依赖 Decimal 的 28 位精度，可处理
  60 位以上数字。
- DISPLAY 无符号写普通数字（F 区位），带符号末位用与解码器一致的正负 overpunch
  （正 C、负 D 区位）。COMP-3 半字节按精确缩放整数填写，前置填充半字节写 0，
  末半字节有符号非负 C/负 D、无符号 F。
- 新值生成确定的规范字节；未指定的原字段即使采用别的合法符号表示也原样保留。

### 同记录多 edit 的重叠合同

更正不是顺序覆盖。每个 edit 是对其完整字段跨度的字节要求：两个路径跨度重叠时，
只有公共位置要求的新字节**逐一相同**才能一起生效；一致的重叠合法，不一致就拒绝
整个作业（不存在“最后一项获胜”，也不会一刀切禁止重定义）。重复同一路径按同一
规则处理。该合同覆盖基字段与替代视图、长度不同的替代视图以及重复组内部的
重定义。

## 交付目录与凭据

输出目录必须**不存在**；成功后包含：

- `original.rewritten.bin`：与原件等长的新原件；
- `rewrite_evidence.json`：机器可读凭据，含
  - 实际输入/输出摘要（SHA-256）与长度；
  - 布局文件摘要（copybook SHA-256）及名称、版本、codec；
  - 每个 edit 的完整路径、记录坐标、绝对字段范围、旧字节与要求的新字节；
  - 按绝对坐标排序、互不交叠、相邻合并的**实际变化区间**及各区间前后字节
    （中间夹着未变字节会被分成两段；只含真正变化的字节）；
  - `counts`：请求字段数、覆盖字节数（重叠只计一次）、真正改变字节数。

凭据不保存整份原件，也不保存每个未改字节的拷贝；读者可凭区间在原件上逐段核对
并重放得到交付文件。

## 边界与资源

- 输入和布局只读；输出目录已存在即拒绝。暂存位置由调用者通过 `--temp-dir`
  提供，作业只在其下创建唯一子目录，并且只清理自己创建的内容（旁边的文件保留）。
- 单记录大小上限 `--max-record-bytes`（默认 16 MiB），在分配记录缓冲**之前**
  检查；分块大小 `--chunk-size`（默认 1 MiB）。
- 任何末尾更正失败、摘要不合、越界、冲突或真实写出失败都返回非零，并清理半成品
  交付；回写文件与凭据对应同一次成功作业。

## 演示与压测

```bash
python3 examples/rewrite/run_demo.py --workdir /tmp/rewrite-demo
python3 tests/rewrite/run_performance.py --size-mib 270 --workdir /tmp/rewrite-perf
```

演示手工构造含两个固定重复组、组内重定义、非零 FILLER、非规范合法符号的记录，
混合两种布局并在记录间放入原样保留的字节；先手算偏移与新旧十六进制，再实际回写，
覆盖一致/冲突重叠、顺序无关、60 位数、定点小数、cp500 文本，并把一段结果交给
现有 `Decoder` 做业务值层核对。压测实跑大于 256 MiB 的原件、稀疏更正首中尾记录，
报告实际大小、峰值内存与耗时，并独立逐字节比较差异集合与凭据区间。
